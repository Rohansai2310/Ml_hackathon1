# Demonstrating the four completed model runs

Open `notebooks/four_models_walkthrough.ipynb` in VS Code or Jupyter. Its saved
outputs were generated by executing cells against the actual recorded experiment
files. Default mode reads saved results without starting another long training job.

Select the **Python (PathSnap)** kernel, backed by the workspace's existing
`.venv/bin/python`. For a new environment, install the project requirements and
`requirements-notebook.txt` before running notebook cells.

Present the notebook in this order:

1. **Input:** show a real Parquet preview and the 22 feature names. Explain that
   each candidate road gets one row and a binary reference-match label.
2. **Validation:** show the five trip folds and the two excluded trips. Explain
   that whole trips stay together, preventing a trip from entering both fitting
   and validation for the same fold.
3. **Training loop:** show the actual `cross_validate` implementation. It creates
   a fresh pipeline per fold, fits preprocessing and the classifier on training
   trips, then scores candidate roads from held-out trips.
4. **Each model:** show its pipeline parameters, five fold scores and sample
   out-of-fold candidate probabilities. Explain that Top-1 picks the highest
   probability candidate per observation.
5. **Comparison:** show recorded mean Top-1 accuracy, candidate Macro F1 and
   binary log loss, followed by the comparison figure.
6. **Evidence:** show the original terminal log and recorded environment. These
   are past experiment outputs, not a live rerun.

The original runs completed four baseline CV experiments, not final model
selection, tuning or student-testing. Temporary fitted fold models were not
retained. Saved results and predictions are available; final deployable model
files are still pending.

## Optional live training

For a live notebook rerun, select the project Python environment and install
`ipykernel` in that environment if VS Code requests it. In the setup cell, change:

```python
RETRAIN_MODELS = {'logistic_regression'}
```

Then run the notebook cells. This reruns all five folds for Logistic Regression
on the complete eligible training data. New CV outputs go to a separate
`outputs/training/walkthrough_<timestamp>/` directory. Other model sections
continue to show recorded results. The original Logistic Regression CV fits
took approximately 80 seconds in total, plus data loading, scoring and file I/O;
actual rerun time varies. Random Forest's five fits took approximately 50 minutes.

The final notebook section includes a terminal command to rerun all four models
and additionally save refitted pipelines. That command deliberately uses a new
directory and does not overwrite the original evidence.

## Regenerate the executed walkthrough

From the repository root with the existing project environment activated:

```bash
PYTHONPATH=src python scripts/create_model_walkthrough.py
```

This executes the default recorded-results cells as Python and captures their
real text outputs into the notebook. It does not fit models or invent results.

## Evidence included in Git

`outputs/experiments/run_001/` contains the recorded fold metrics, comparison
plots, environment, run metadata, original logs and six-row candidate-score
samples. The notebook reads this archive by default. Rebuild feature Parquets
from the raw dataset before re-executing its input-data cells. Full prediction
CSVs remain local under `outputs/training/run_001/`; samples are for inspection
only and cannot reproduce aggregate metrics or resume training.
